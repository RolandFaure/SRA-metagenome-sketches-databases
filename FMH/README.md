## Decompressing the archive

The decompression pipeline for reconstructing original `sourmash` `.sig` files from a compressed FracMinHash sketch database generated by our compression pipeline.
A demo compressed archive, `compressed_hashes.tar.xz`, is included to demonstrate the output produced by our compression algorithm.

### Requirements

- Linux
- Bash
- Python 3
- C++17 compiler (`g++`)

### Clone the Repository 

Clone the main repository and enter the `FMH` folder:

```bash
git clone https://github.com/RolandFaure/SRA-metagenome-sketches-databases.git
cd SRA-metagenome-sketches-databases/FMH
``` 

## Decompression 

```bash
chmod +x decompression_pipeline.sh
./decompression_pipeline.sh <compressed_hashes.tar.xz> <output_directory> [threads]
```

### Arguments

| Argument | Description |
|----------|-------------|
| `compressed_hashes.tar.xz` | Path to the compressed FracMinHash sketch archive. |
| `output_directory` | Directory where decompression outputs and reconstructed `.sig` files will be stored. |
| `threads` | Optional number of threads to use during decompression. Default: `128`. |

## Example

Using default number of threads:

```bash
./decompression_pipeline.sh compressed_hashes.tar.xz .
```
Using custom number of threads:

```bash
./decompression_pipeline.sh compressed_hashes.tar.xz . 256
```

After successful completion, the reconstructed `.sig` files and the archived `VERSION` file are retained inside the decompression directory.
```text
decompressed_sigs/
    ├── VERSION
    └── sigs/
        ├── accession_1.sig
        ├── accession_2.sig
        └── ...
```
---

### Archive Compatibility

The decompressor verifies the archive version before extraction. Archives generated by unsupported versions of the compression pipeline will be rejected.

## Help

Display the command-line help message with:

```bash
./decompression_pipeline.sh --help
```

## Toy Dataset and Additional Scripts

The scripts used by the compression pipeline, along with full usage instructions, are available in [compression_scripts/](compression_scripts/).

The scripts used to validate the reconstructed signatures through unit testing are available in [test/](test/).

The toy dataset can be used to test the complete workflow by compressing the original signatures, decompressing the generated archive, and comparing the reconstructed signatures against the original toy signatures using the unit-testing script.
